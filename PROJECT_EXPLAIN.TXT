1. PROJECT EXECUTIVE OVERVIEW
================================================================================
Ironclad Gaming Sanctuary is an esports gaming lounge and cafe management 
platform originally forged for an elite gaming lounge located at:
  Behind Redtape Showroom, Near PSPCL Office, Guru Angad Dev Nagar,
  Sri Muktsar Sahib, Punjab – 152026.

The platform has been completely generalized and white-labeled so that any 
gaming cafe owner anywhere in the world can run, rebrand, and customize the 
entire application directly from the web-based Administrator Panel without 
editing any source code.

KEY OBJECTIVES DELIVERED:
- Provide customers with real-time seat availability and frictionless online booking.
- Prevent double bookings with zero race conditions (including late-night sessions).
- Enable seamless Indian UPI payments (GPay, PhonePe, Paytm, BHIM) with automated QR.
- Dedicated player account suite with mobile/email sign-in, booking history, and dashboard.
- Admin Customer CRM with 1-click WhatsApp festival/offer mass broadcasting.
- Contact inquiries inbox with automated lead capture into the customer registry.
- Role-based admin accounts (Owner, Receptionist/Staff, Developer) with lockout prevention.
- Immersive atmospheric visual engine with high-visibility cafe and GTA 6 backgrounds.
- Generate high-impact 1-page printable passes and instant downloadable PDFs.
- Enable instant WhatsApp messaging with deep links and delivery status tracking.
- Allow owners to customize Cafe Name, Logo, Tour Video, Hero Headlines, Address,
  and Amenities in real time.
- Present gamer-friendly hospitality policies: 4K + QLED screens, cozy aesthetic 
  ambience, in-house chilled beverages/packed food, and 100% outside food allowed.

3. DATABASE SCHEMA & DATA RELATIONSHIPS
================================================================================
The normalized relational database `ironclad_gaming` consists of the following 
primary tables:

1. `station_categories`: PC Battle Rigs, PS5 Console Lounges, Squad LAN Bays.
2. `stations`: Individual hardware stations, specs, hourly rates, active/maintenance status.
3. `pricing_plans`: Packaged multi-hour passes (1 Hr, 2 Hrs, 3 Hrs, Full Day Pass).
4. `special_offers`: Promo codes, percentage or flat discounts, validity dates, min hours.
5. `customers`: Player directory, full name, phone number, email, hashed password,
   total bookings, lifetime spend, account creation timestamp.
6. `bookings`: Master reservations table storing station_id, customer_id, booking_date,
   start_time, end_time, duration_hours, total_amount, discount_amount, final_amount,
   booking_status (confirmed, pending_payment, cancelled, completed), reference number.
7. `payments`: Payment records, amount, payment_method (upi_qr, razorpay, cash), status,
   transaction_ref (12-digit UTR).
8. `inquiries`: Customer contact form submissions (name, email, phone, subject, message,
   status: new/replied/closed, admin_notes, timestamps).
9. `users`: Administrative user accounts (id, username, email, password_hash, role:
   super_admin/staff/developer, is_active, last_login).
10. `reviews`: Customer feedback, ratings (1-5 stars), game played, approval status.
11. `gallery`: Visual photos and video reels with category tags and display order.
12. `activity_logs`: Administrative audit trail logging user_id, action, details, IP.
13. `settings`: Key-value configuration store for dynamic white-label properties.

5. PROBLEMS ENCOUNTERED DURING DEVELOPMENT & HOW WE SOLVED THEM
================================================================================

5.1. THE MIDNIGHT-CROSSING DOUBLE-BOOKING BUG
- Symptom: A booking starting at 22:30 for 2 hours ends at 00:30 next day. SQL comparison
  `start_time < new_end AND end_time > new_start` failed due to `00:30 < 22:30`.
- Solution: Transitioned time clash logic to full ISO datetime stamps (`booking_date + start_time`).

5.2. SQLSTATE[HY093] PARAMETER BINDING ERROR
- Symptom: Duplicate named placeholders in PDO queries caused statement preparation errors.
- Solution: Assigned unique named placeholders per clause (`:bdate1`, `:bdate2`).

5.3. MULTI-PAGE RECEIPT PRINT SPILLOVER
- Symptom: Default print stylesheets pushed receipts onto two pages.
- Solution: Added strict `@media print` rules setting `@page { size: A4 portrait; margin: 8mm; }`,
  restricting container heights, and hiding non-essential headers/footers.

5.4. CUSTOMER NAME CASE INCONSISTENCY
- Symptom: Users typed names in all-lowercase or all-caps.
- Solution: Created `to_title_case()` sanitizing input to proper Title Case across all forms.

5.5. LANDING PAGE VIDEO CLUTTER & PAGE WEIGHT
- Symptom: Multiple auto-playing MP4 videos slowed mobile page load speeds.
- Solution: Restricted hero banner to a single optimized loop; shifted secondary tour video
  to an on-demand Bootstrap modal with lazy-loading memory disposal.

5.6. HARDCODED BRAND IDENTITY DECOUPLING
- Symptom: Original Muktsar brand details were hardcoded across multiple views.
- Solution: Centralized all brand attributes in `settings` table via `get_brand_*()` helpers.

5.7. CONFLICTING FOOD & BEVERAGE POLICY ON PASSES
- Symptom: Outdated text stated "No outside food allowed", conflicting with cafe policy.
- Solution: Aligned all receipts, passes, FAQs, and cards to confirm outside food is 100% allowed
  and in-house chilled beverages & packed snacks are available.

5.8. SESSION & CONFIG LOADING ORDER IN PUBLIC VIEWS
- Symptom: Calling `session_start()` after output triggered headers already sent warnings.
- Solution: Standardized `config/config.php` to initialize sessions prior to any output.

5.9. BACKGROUND IMAGE OPACITY CRUSHING VISIBILITY ON SCROLL
- Symptom: Overlays with 0.88–0.94 black opacity made atmospheric backgrounds virtually invisible.
- Solution: Lightened gradient overlays to 0.15–0.25 opacity in the center, wrapped text in
  frosted glass cards (`backdrop-filter: blur(14px)`), and added a dynamic scroll visibility
  enhancer in `main.js`.

5.10. BROWSER ASSET CACHING HIDING IMMEDIATE VISUAL UPDATES
- Symptom: Browsers cached CSS and JS files, showing old button colors and styles.
- Solution: Added automated cache-busting query strings `?v=<?= APP_VERSION ?>_<?= time() ?>`
  in `header.php` and `footer.php`.

5.11. AMBIGUOUS CUSTOMER PHONE IN JOINED BOOKING HISTORY QUERIES
- Symptom: `my-account.php` threw SQL column error `b.customer_phone` not found on `bookings`.
- Solution: Resolved query to `JOIN customers c ON b.customer_id = c.id` and matched against
  customer ID and phone correctly.

7. STEP-BY-STEP DEPLOYMENT & MAINTENANCE GUIDE
================================================================================
TO RUN ON LOCAL XAMPP:
1. Ensure Apache and MySQL are running in the XAMPP Control Panel.
2. Place the project directory in: `C:\xampp\htdocs\GamingCafe\`
3. Verify the database `ironclad_gaming` exists in phpMyAdmin (`http://localhost/phpmyadmin/`).
4. Import `database/schema.sql` and run any pending migrations:
   - `http://localhost/GamingCafe/database/migrate_customers.php`
   - `http://localhost/GamingCafe/database/migrate_inquiries.php`
5. Database connection settings are in `config/database.php` and `.env`:
   Host `127.0.0.1`, User `root`, Password `` (empty).
6. Open in browser:
   - Public Website: `http://localhost/GamingCafe/`
   - Player Login:   `http://localhost/GamingCafe/login.php`
   - Admin Panel:    `http://localhost/GamingCafe/admin/login.php`
   - Default Owner Login Credentials:
     Username: `admin`
     Password: `IroncladAdmin2026!`
7. To rebrand for another cafe:
   - Navigate to **Website Settings** (`admin/settings.php`).
   - Update cafe details, upload custom logo/video, and click **Save & Apply**.
